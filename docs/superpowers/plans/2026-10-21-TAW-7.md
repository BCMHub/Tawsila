### T4 (I) Secure session storage
- **Objective:** a session store that cannot expose a partial or mixed session.
- **Dependencies:** T1.
- **Components:** `apps/mobile/src/features/auth/secureStorage.ts` and its test file.
- **Interface (fixed):** `createSecureStorage(store, options?: { chunkSize?: number })` returns `{ getItem, setItem, removeItem }` (promises; `getItem` gives string or null); `store` provides `getItemAsync`, `setItemAsync`, `deleteItemAsync`; `export const secureStorage = createSecureStorage(SecureStore)`.
- **Required behaviour:** spec section 4 "Session storage": ASCII values only; every entry below the chunk size; replacement writes a fresh generation and only then the manifest, so a reader follows the manifest only; an interrupted replacement leaves the previous session readable; a missing or corrupt manifest or chunk reads as no session and is cleaned; unreferenced generations are pruned, including when found by a **different adapter instance over the same store** (the app's restart case); operations on an instance are serialized; removal deletes the manifest first and then every generation and leaves the store empty; no operation ever returns a value assembled from two generations.
- **Test-first (against an in-memory fake store with write-failure injection and a second adapter instance):** round trip of a multi-chunk value and the size bound; unknown key and non-ASCII rejection; a replacement interrupted at **every** write boundary leaves the old value readable and a retry succeeds with no orphans; a first write interrupted at every boundary reads as null and a retry is clean; **process termination during a replacement** is modelled by abandoning the instance mid-write and reading through a new instance, which returns the old value or null and never a mix, and whose next write prunes the orphans; each stored entry (every key, from the very store being damaged) deleted or replaced by garbage in turn yields null or the full value and the adapter then recovers with no orphans; concurrent writes through one instance end as one complete value with no orphans; removal after several replacements leaves the store empty.
- **Verification:** `npx jest src/__tests__/auth/secureStorage.test.ts`, `tsc`, lint. **Evidence:** test output. **Completion:** all cases green and the diff review confirms no mixed read path.

### T5 (I) AuthProvider: session authority, provider sign-in, fresh-install rule
- **Objective:** the app's single source of authentication state, derived from the SDK session and the own account row.
- **Dependencies:** T1, T3 (for the row contract), T4.
- **Components:** `apps/mobile/src/features/auth/AuthProvider.tsx`, `apps/mobile/src/lib/supabase.ts`, a test double `apps/mobile/src/__tests__/helpers/fakeAuthClient.ts` and the test file.
- **Interface (fixed):** `ProviderName = 'google' | 'apple'`; `ProviderResult = { idToken; nonce?; fullName? }`; `ProviderHandlers` (handlers reject with `{ code: 'cancelled' | 'denied' | 'unavailable' }` or an error); `InstallGuard = { isFreshInstall(): Promise<boolean> }`; `AuthState = 'checking' | 'signed_out' | 'authenticating' | 'account_provision_error' | 'needs_profile' | 'ready_to_browse'`; `Notice = 'offline' | 'failed' | 'provider_failed' | 'unavailable' | null`; `useAuth()` returns `{ state, canRetry, notice, signIn(provider), retry() }`; `<AuthProvider client providers installGuard timeoutMs?>`.
- **Required behaviour:** state derivation per spec section 4 (no session: `signed_out`; an attempt running: `authenticating`; session with the own-row read pending: `checking`; row missing or read failed: `account_provision_error` with retry; row with `profile_completed_at` null: `needs_profile`; set: `ready_to_browse`); the six session invariants of spec section 4; on `SIGNED_OUT` the controller re-reads the SDK session (still present: stale, ignore; absent: sign out once; read fails temporarily (network or 5xx) or reports `AuthRefreshDiscardedError`: clear nothing, a notice only for the temporary case); late results of timed-out or unmounted operations change nothing, and the app starts nothing once unmounted (a token exchange the SDK already holds cannot be cancelled: its completion is the SDK's own change and the app takes no further action for it); the Apple name update is optional (its failure never fails the sign-in); the raw nonce goes to `signInWithIdToken`; a second tap or a repeated result creates one session; **every sign-out the app itself performs uses `signOut({ scope: 'local' })`, never the default global scope**; **fresh-install rule (D2): when `isFreshInstall()` is true or throws, the app ends any stored session with a local sign-out and clears the stored session data; when false the session is kept**.
- **Test-first (against the fake client; each test named after its rule):** cold start with no session; with a session and each row state (incomplete profile, completed, missing, network error with a notice and no sign-out); a slow row read shows `checking` and never `ready_to_browse` or a sign-out; Google and Apple success (token exchange once, with the raw nonce); the Apple name stored once and a failing name update leaving the session and navigation intact; cancelled, denied, unavailable, empty token and unexpected error each end on `signed_out` with no session and the right notice; a second tap while authenticating calls the handler once; invariants: a stale `SIGNED_OUT` with a valid SDK session is ignored, genuine termination signs out once, a temporary read failure and a discarded refresh never sign out, unmount before the provider answers does nothing, a token exchange already running at unmount leaves the app inactive (no read, no name update, no sign-out), a row read that outlives its timeout is abandoned and its late answer is ignored, a provider event alone never reaches `ready_to_browse`; **local versus global scope: the fake records the sign-out arguments and every app-initiated sign-out (fresh-install, genuine termination) is `{ scope: 'local' }`, none is global or defaulted**; fresh installation with a surviving session signs out locally and requires sign-in, a normal update keeps the session, and a guard that throws requires sign-in.
- **Verification:** `npx jest src/__tests__/auth/AuthProvider.test.tsx`, `tsc`, lint. **Evidence:** test output. **Completion:** all green; the diff review traces each invariant to code.
