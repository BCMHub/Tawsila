# TAW-4 Profile, consent and identity verification implementation plan (criteria revision 6)

**Goal:** After Google sign-in a new user completes onboarding (name, 18+, Terms and Privacy, community, role) and reaches browsing through a server-confirmed state; before the first ride the user submits identity documents (National ID for everyone; driver's license, car license and car data for car owners) for manual review by the owner, with server-owned statuses and eligibility functions for the ride cards.

**Spec:** `docs/superpowers/specs/2026-10-25-TAW-4-design.md`, gated blob `768c76a2fa53c690c7ff3a1cdb3505fbdffb7ee0` (spec gate PASS, round 3). **Criteria:** TAW-4 revision 6 (AC1-AC18), snapshot sha256 `30f2f0c11673c4c5ae9e2dd65303a4649f2a4413228b2468269be90e68263c2f`. **Design:** Figma file 2j3vO1USLBA8XiRpQKCF3H, section 186:605 (20 light and 20 dark frames, approved). **Stack:** Expo SDK 58 (~58.0.16), React Native 0.88.0, TypeScript strict, Expo Router, jest-expo, `@supabase/supabase-js` ^2.118, Supabase CLI with the local Docker stack, pgTAP.

**MVP execution scope (owner decision 2026-10-25, criteria revision 7): section 3a governs this implementation; the tasks and parts it marks as skipped are parked for a later card, not removed.** **Plan format.** Each task states its objective, class, dependencies and prerequisites, affected components, required behaviour, test-first requirements, verification commands, expected evidence and completion criteria. **The implementing agent writes the code and the tests from these requirements, tests first.** This plan contains no implementation code. Section and verification-item numbers (V1 to V13, O1 to O9, B1, B2) refer to the spec.

**Allowed paths (proposed for the TAW-4 card, none under `docs/superpowers/`):** `apps/mobile/` (including native configuration and the `app.json` fields the owner approves), `supabase/` (config, migrations, tests, seed and fixtures, README), `.gitignore`, `README.md`. `docs/product/mvp.md` is not included (spec O7). **Never invented:** Figma IDs, credentials, package versions, car data, legal text versions: they come from the owner, discovery or the tasks below and stay blank until verified.

**Execution controls (CLH framework).** Notion cards and READY gates stay mandatory; work happens only in a dedicated worktree; implementer and reviewer contexts follow the 40% ceiling of AGENTS.md; tests first; TAW-5, TAW-6 and other cards are not modified; no external project, purchase or deployment is created; only synthetic identities and the local stack or the owner's hosted test project are used; before any node command run `. /Users/sherifehab/Developer/Tawsila/.clh/evidence/TAW-3/node24.env`, and run `unset EXPO_NO_DOTENV` before Expo runs that need `.env`. ### T2 (I) Database tests first
- **Objective:** the failing pgTAP files that define the contract of spec section 3.
