# TAW-5 Deferred phone verification implementation plan (criteria revision 3, project-owned OTP)

**Goal:** Before a signed-in user's first ride offer or first ride request, the user verifies a phone number with a six-digit WhatsApp code. The project owns the code (two Edge Functions plus security-definer database functions); `accounts.phone_verified` changes only through `verify_phone_challenge`. Browse, onboarding, profile and community stay ungated.

**Spec:** `docs/superpowers/specs/2026-10-26-TAW-5-design.md`, gated blob `fddd9170e453625d6aef86c097ea52f5eee14204` (spec gate PASS, round 14, commit `57161dd`; amended 2026-10-26 after the owner's review decisions, which voided the round-11 PASS); companion ADR blob `1e147facd07694e7a1f0c98e463def0f30ae316e`. The plan itself was amended after the owner's review decisions; its earlier plan-gate PASS (round 3) is void until the plan gate is re-run. **Criteria:** TAW-5 revision 3 (AC1-AC12), snapshot sha256 `6463dd06acd73b77db18360ae58549c51dfeaf3c40704546bc475afc1fd9aa07`. **Design:** Figma file `2j3vO1USLBA8XiRpQKCF3H`, section `214:1809` (owner-approved, design card DONE). The spec governs wherever this plan is silent; section 5.1 of the spec (lifecycle and response table) and section 15 (privilege matrix) are binding test sources.

**Allowed paths (proposed for the TAW-5 card, none under `docs/superpowers/`):** `supabase/migrations/` (one new file), `supabase/functions/phone-otp-start/`, `supabase/functions/phone-otp-verify/`, `supabase/functions/_shared/`, `supabase/tests/database/` (including its subfolder `concurrency/` for the multi-connection scripts, run by an explicit command; `supabase test db` ignores shell scripts), `supabase/config.toml` (function settings and local sandbox only), `apps/mobile/src/features/phoneVerification/`, `apps/mobile/src/app/` (the gate route only), `apps/mobile/src/strings.ts`, `apps/mobile/src/__tests__/phoneVerification/`, `.env.example`, `.gitignore`, `README.md`. No auth files, no TAW-4 functions, no hosted-project change.

**Execution controls.** Notion cards and READY gates stay mandatory; dedicated worktree; tests first for every I task (Critical lane: full TDD); implementer and reviewer contexts stay under the 40% ceiling of AGENTS.md; TAW-4, TAW-6, TAW-7 and the auth files are not modified; no external project, purchase, deployment, secret read or print; the lean-document lesson of TAW-8 applies (no implementation code in this plan for intricate components, required behaviour and tests instead).

**T8a (V2, hosted session-lifecycle test with session-state changes):** (1) the owner signs in with Google on a development build pointed at `tawsila-dev`; (2) a debug-only helper kept outside the repository reads the session's access token without printing it and records only the claim names and whether `session_id` exists; (3) the helper calls `GET /auth/v1/user` with the token (expect 200), refreshes the session and records whether `session_id` is unchanged; (4) the owner signs out in the app; (5) the helper replays the old access token against `GET /auth/v1/user` (expect 403 `session_not_found`); (6) the evidence file keeps status codes and claim names only. The only hosted state it changes is the owner's own Auth session (created at sign-in, rotated at refresh, revoked at sign-out); the exact-step authorization names those three actions; no table, setting or function is touched.

**T8 (Tier 2, shared state):** applying the migration to `tawsila-dev` and enabling `pg_cron`, deploying `phone-otp-start` and `phone-otp-verify`, setting the three secrets by name, and a few WhatsApp messages to the owner's own number. The owner authorizes the exact commands before any of them runs.
