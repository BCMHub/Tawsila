# TAW-5 Deferred phone verification implementation plan (criteria revision 3, project-owned OTP)

**Goal:** Before a signed-in user's first ride offer or first ride request, the user verifies a phone number with a six-digit WhatsApp code. The project owns the code (two Edge Functions plus security-definer database functions); `accounts.phone_verified` changes only through `verify_phone_challenge`. Browse, onboarding, profile and community stay ungated.

**Spec:** `docs/superpowers/specs/2026-10-26-TAW-5-design.md`, gated blob `3c2ae28aa097aa6547de334b7797a8adddf8c902` (spec gate PASS, round 11, commit `21f7848`); companion ADR blob `85bcef84552ca644c38a1aa1eb8b8829922c58fe`. **Criteria:** TAW-5 revision 3 (AC1-AC12), snapshot sha256 `6463dd06acd73b77db18360ae58549c51dfeaf3c40704546bc475afc1fd9aa07`. **Design:** Figma file `2j3vO1USLBA8XiRpQKCF3H`, section `214:1809` (owner-approved, design card DONE). The spec governs wherever this plan is silent; section 5.1 of the spec (lifecycle and response table) and section 15 (privilege matrix) are binding test sources.

**Allowed paths (proposed for the TAW-5 card, none under `docs/superpowers/`):** `supabase/migrations/` (one new file), `supabase/functions/phone-otp-start/`, `supabase/functions/phone-otp-verify/`, `supabase/functions/_shared/`, `supabase/tests/database/`, `supabase/tests/concurrency/`, `supabase/config.toml` (function settings and local sandbox only), `apps/mobile/src/features/phoneVerification/`, `apps/mobile/src/app/` (the gate route only), `apps/mobile/src/strings.ts`, `apps/mobile/src/__tests__/phoneVerification/`, `.env.example`, `.gitignore`, `README.md`. No auth files, no TAW-4 functions, no hosted-project change.

**Execution controls.** Notion cards and READY gates stay mandatory; dedicated worktree; tests first for every I task (Critical lane: full TDD); implementer and reviewer contexts stay under the 40% ceiling of AGENTS.md; TAW-4, TAW-6, TAW-7 and the auth files are not modified; no external project, purchase, deployment, secret read or print; the lean-document lesson of TAW-8 applies (no implementation code in this plan for intricate components, required behaviour and tests instead).
